    Tailscale – Overall Overview and Recommendations¶

    Based on our discussions, Tailscale looks like a very interesting solution for your infrastructure. It could give you secure remote access to your Linux VMs, WSL2 development environment, web applications and other services without exposing them directly to the internet.

    Below is a consolidated overview of what we discussed, including the security considerations and my recommendations.

    1. What is Tailscale?¶

    Tailscale is a mesh VPN solution built on top of WireGuard.

    It creates a private network between your devices, regardless of their physical location.

    For example, you could connect:

    • Windows 11 desktop.
    • Ubuntu running inside WSL2.
    • Remote Linux VMs.
    • Android smartphone.
    • Home Assistant.
    • Docker servers.
    • Other Linux machines.

    All these devices become part of your private network.

    Each device receives a private Tailscale IP address, generally in the 100.x.x.x range.

    You can communicate between devices as if they were connected to the same local network.

    Official website: Tailscale

    2. How does the network operate?¶

    Tailscale uses WireGuard encryption to establish secure connections.

    There are two possible connection methods.

    A. Direct connection (preferred)¶

    Windows PC
     |
     | WireGuard encrypted
     |
Internet
     |
     | WireGuard encrypted
     |
Linux VM

    The traffic travels directly between your devices.

    Tailscale's coordination servers help establish the connection but do not carry the actual traffic.

    B. DERP relay¶

    If a direct connection cannot be established, Tailscale can use a relay server.

    Windows PC
     |
     | Encrypted traffic
     |
Tailscale DERP server
     |
     | Encrypted traffic
     |
Linux VM

    Even when using a relay, the traffic remains encrypted.

    Can Tailscale see your data?¶

    Generally, no.

    Information Tailscale access
    SSH passwords No
    SSH private keys No
    Terminal contents No
    Files transferred No
    HTTP application contents No
    Device IP addresses Yes
    Device identities Yes
    Connection metadata Yes
    Traffic volume and timing Potentially

    There are two independent encryption layers when using SSH:

    1. WireGuard encryption between devices.
    2. SSH encryption between the SSH client and server.

    You are still trusting Tailscale's coordination infrastructure to manage device identities and network configuration correctly.

    3. Security and vulnerability management¶

    We discussed whether Tailscale is sufficiently secure and how well it manages vulnerabilities.

    My assessment is that Tailscale is a mature security-focused product.

    However, it is important to distinguish between two things:

    What Tailscale protects: - Network communications. - Remote access. - Device authentication. - Unauthorized network connections. - Exposure of services to the public internet.

    What Tailscale does not protect: - Vulnerabilities in Linux. - Vulnerable Docker containers. - Vulnerable web applications. - Malware running on your machines. - Compromised Windows installations. - Vulnerabilities in Tailscale itself.

    You should therefore maintain normal security practices:

    • Keep Tailscale updated.
    • Enable MFA.
    • Restrict device access.
    • Keep Linux security updates enabled.
    • Use SSH public/private key authentication.
    • Disable SSH password authentication.
    • Disable root SSH login.
    • Apply firewall rules.

    Tailscale also publishes security advisories:

    Tailscale Security Bulletins

    4. Windows 11 versus WSL2 installation¶

    This was one of the more interesting aspects of our discussion.

    There are two installation possibilities.

    Option A: Install Tailscale on Windows¶

           Windows 11
           |
       Tailscale
           |
          WSL2
           |
        Ubuntu
           |
       SSH / HTTP

    Advantages: - Simple installation. - All Windows applications can access the Tailscale network. - WSL2 can use the Windows network connection. - Easy integration with VS Code. - No additional VPN installation inside Ubuntu.

    Disadvantages: - Installs a privileged Windows service. - Adds a virtual network interface. - Adds another component to your Windows attack surface.

    Option B: Install Tailscale inside WSL2¶

           Windows 11
           |
          WSL2
           |
        Ubuntu
           |
       Tailscale
           |
       WireGuard
           |
        Internet

    Advantages: - No additional Tailscale service on Windows. - Separate Tailscale device identity. - VPN functionality managed by Linux.

    Disadvantages: - More complicated networking configuration. - WSL2 networking limitations. - Windows applications do not automatically become Tailscale-connected devices.

    My preference, considering your security concerns, is to investigate the WSL2 installation first.

    One important qualification: WSL2 is not a complete security boundary. It shares the Windows host's underlying kernel infrastructure.

    Also, don't run independent Tailscale installations in Windows and WSL2 simultaneously unless you have a specific reason and understand the networking implications.

    Documentation:

    Tailscale WSL2 documentation

    5. Remote SSH access to Linux¶

    This was your original requirement.

    With Tailscale, you can access your Linux VM without exposing SSH to the public internet.

    For example:

    ssh username@100.x.y.z

    You don't need: - Public IP addresses. - Router port forwarding. - Publicly exposed SSH ports. - Dynamic DNS. - An externally accessible SSH server.

    I recommend retaining standard OpenSSH rather than using Tailscale SSH.

    This means: - Your SSH server remains OpenSSH. - You manage your own SSH keys. - Tailscale only provides private network connectivity. - SSH authentication remains independently managed.

    6. Web application development and testing¶

    We also discussed whether Tailscale can be used for web application development.

    The answer is yes.

    You can access web applications running on any connected machine.

    For example, suppose you run a Next.js application on your Linux VM:

    npm run dev -- --hostname 0.0.0.0

    You can access it from Windows using:

    http://100.x.y.z:3000

    You can also do the reverse: run applications on Windows and access them remotely from Linux or Android.

    Typical applications include:

    Application Example
    Next.js Port 3000
    Vite Port 5173
    Node.js API Port 8080
    Portainer Port 9443
    Home Assistant Port 8123
    Grafana Port 3000

    You should restrict access to trusted devices and avoid exposing development servers unnecessarily.

    Tailscale Serve¶

    Another interesting feature is Tailscale Serve.

    It allows you to expose a local web application to your private Tailscale network using HTTPS.

    For example:

    tailscale serve --bg 3000

    This provides an HTTPS address for accessing your application.

    Documentation: Tailscale Serve

    7. Android support¶

    Tailscale has an official Android application.

    Download:

    Tailscale Android – Google Play

    You can use it to:

    • SSH into Linux machines.
    • Access web applications.
    • Access Home Assistant.
    • Access Portainer.
    • Access private APIs.
    • Access your development environment.

    It works over mobile data and public Wi-Fi.

    You simply authenticate using the same Tailscale account.

    8. Tailscale versus alternatives¶

    We also discussed WireGuard and OpenVPN.

    Here is the comparison:

    Feature Tailscale WireGuard OpenVPN
    Underlying protocol WireGuard WireGuard OpenVPN
    Encryption Excellent Excellent Excellent
    Peer-to-peer Yes Yes Depends on configuration
    Automatic NAT traversal Yes Requires configuration Depends on configuration
    Central coordination Tailscale Self-managed Self-managed
    Self-hosting Headscale Yes Yes
    Configuration complexity Low Medium Medium/high
    Open source Client components Yes Yes

    Headscale¶

    We also discussed Headscale.

    Headscale is an open-source, self-hosted implementation of the Tailscale coordination server.

    Headscale GitHub repository

    It offers an interesting alternative if you want to retain the Tailscale client experience while controlling the coordination infrastructure yourself.

    9. Proposed architecture¶

    Taking everything into account, this is the architecture I would investigate for your environment:

                           INTERNET
                           |
                    Tailscale Network
                           |
             +-------------+-------------+
             |             |             |
          Windows        Android       Linux VM
           11             Phone        Remote
             |                           |
           WSL2                        OpenSSH
             |                           |
         Development                  Docker
             |                           |
         Node.js /                   Applications
          Next.js                    Portainer
                                      Home Assistant
                                      APIs

    The idea is to have a private network connecting your development environment, remote infrastructure and mobile devices.

    Your existing OpenVPN installation can remain independent. You don't need to replace it.

    10. My final recommendations¶

    Based on our discussions, I would prioritize the following:

    Priority Recommendation
    1 Use Tailscale for private remote connectivity
    2 Investigate installation inside WSL2
    3 Retain standard OpenSSH
    4 Use SSH keys exclusively
    5 Enable MFA
    6 Restrict access using Tailscale ACLs/grants
    7 Avoid exposing SSH and development ports publicly
    8 Keep Linux and Tailscale updated
    9 Install Tailscale on Android for mobile access
    10 Investigate Headscale if you eventually want self-hosted coordination

    Overall conclusion¶

    I think Tailscale is a particularly good fit for your requirements.

    The three main benefits are:

    1. Security: You eliminate the need to expose SSH and development services directly to the internet.
    2. Convenience: You can access your infrastructure from Windows, WSL2, Linux and Android.
    3. Development: You can develop applications on one machine and test them remotely on another without configuring public networking.
